## [1.11.0] - 2026-04-12

### IdeaEngine 重构 - 研究想法生成系统

**文件**: `idea_engine.py`, `main.py`

**概述**: 重构 IdeaEngine 为完整的**研究想法生成系统**，整合 Bright Data 网络搜索 + 本地 Paper RAG + LLM 生成，支持想法的持久化存储和管理。

**新增 Topic 管理系统**:

| 方法 | 说明 |
|------|------|
| `_get_ideas_dir()` | 获取想法存储根目录 `plugin_data/astrbot_plugin_paperrag/ideas` |
| `_topic_folder()` | 使用 MD5 哈希（前16位）作为文件夹名，跨进程稳定 |
| `_topic_hash()` | 计算 topic 的哈希值 |
| `_get_topic_index()` | 获取 `folder_name → topic` 映射索引 |
| `_save_topic_index()` | 保存 `topic → folder_name` 索引到 `topic_index.json` |
| `find_topic_by_folder()` | 根据 folder name 查找对应 topic |
| `list_all_topics()` | 列出所有已保存的 topic 及元信息（想法数量、创建时间） |
| `delete_ideas_by_uuids()` | 根据 UUID 列表删除想法文件 |

**存储结构**:
```
plugin_data/astrbot_plugin_paperrag/ideas/
├── topic_index.json           # folder_name → topic 索引
└── <hash>/                    # 每个 topic 一个文件夹（MD5前16位）
    ├── context.json           # 主题分析上下文
    ├── <uuid1>.json           # 每个想法独立文件
    ├── <uuid2>.json
    └── ...
```

**Bright Data MCP 工具集成**:

| 方法 | 说明 |
|------|------|
| `search_with_brightdata()` | 使用 Bright Data `search_engine` 工具进行网络搜索 |
| `scrape_with_brightdata()` | 使用 `scrape_as_markdown` 工具抓取网页内容 |
| `discover_with_brightdata()` | 使用 `discover` 工具发现相关主题 |

- MCP 服务器输出可能包含多行（错误日志+JSON），修复为逐行查找第一个有效 JSON 对象

**知识融合 (Knowledge Fusion)**:

| 方法 | 说明 |
|------|------|
| `search_knowledge()` | 融合本地 RAG + 网络搜索结果，统一返回 `fused_context` |
| `fuse_knowledge()` | 合并 local_rag_context 和 web_context |

**VLM 图片分析优化**:

| 方法 | 说明 |
|------|------|
| `_generate_image_summary_with_qwen()` | **文字优先策略**：优先提取图片中的文字，仅在无文字时 fallback 到视觉分析 |

- 提升论文截图、表格等文字密集图片的识别准确率
- 页码显示优化：仅在有页码时显示

**新增 `/idea` 命令组**:

| 命令 | 说明 |
|------|------|
| `/idea gen <研究主题>` | 生成研究想法并保存（分析主题 → 检索知识 → 生成想法 → 保存到文件） |
| `/idea list` | 列出所有已保存的 topic 及想法数量 |
| `/idea show <topic>` | 显示单个 topic 下所有想法详情 |
| `/idea add <topic>` | 为已有 topic 追加新想法 |
| `/idea del <uuid>` | 删除指定 UUID 的想法 |
| `/idea tofeishu <topic> [folder_token]` | 将想法导出为飞书文档（第二阶段） |

### 评估流程优化 - 多项 Bug 修复与参数增强

**概述**: 修复评估脚本多项问题，新增命令行参数，完善评测能力。

**评估脚本修复**:

1. **eval_embedding_mode 参数传递修复**
   - 文件: `evaluation/run_evaluation_ragas.py`
   - 问题: `--step evaluate` 调用时未传递 `eval_embedding_mode` 参数，导致默认使用 API 而非 Ollama
   - 修复: 在 `run_evaluation()` 调用处添加 `eval_embedding_mode=args.eval_embedding_mode`

2. **top_k 命令行参数**
   - 新增 `--top-k` 参数，支持运行时覆盖配置文件中的 top_k 值
   - 便于测试不同检索数量对指标的影响

3. **enable_two_stage_retrieval 配置传递**
   - 修复: 两处 RAGConfig 创建均添加 `enable_two_stage_retrieval` 字段
   - 确保评估时与配置文件一致

4. **has_multimodal 统计修复**
   - 文件: `evaluation/ragas_evaluator.py`
   - 问题: `has_multimodal` 用检索结果推断，而非测试集原始标记
   - 修复: 直接使用测试集的 `is_multimodal` 字段

5. **used_images 空值修复**
   - `r.get("used_images")` 在值为 None 时返回 None 而非默认值
   - 修复: `r.get("used_images") or []`

6. **raw_answers 实际数量显示**
   - `--step evaluate --skip-rag` 时显示 `raw_answers.json` 实际问题数量

**pymilvus API 兼容性修复**:

7. **AbstractIndexManager.search_by_abstract()**
   - 文件: `abstract_index.py`
   - 问题: `pymilvus 2.x` 中 `Collection.search()` 不接受 `collection_name` 参数
   - 修复: 移除多余的 `collection_name` 参数

**相对导入修复**:

8. **hybrid_rag.py AbstractIndexManager 导入**
   - 问题: `from .abstract_index` 在 `python -m` 模式下相对导入失败
   - 修复: 添加 `except ImportError` fallback 到绝对导入

**评估指标分析**:

- 通过多组实验（VL-5, VL-10, VL-abstract）对比分析 top_k 和两阶段检索对 cr/cp 的影响
- 结论: 当前配置下 answer_correctness 已达瓶颈，precision/recall 提升被其他因素抵消
