### 知识图谱实体名称去重：别名/缩写规范化

本次更新实现了完整的 4 层实体名称去重体系，解决同一实体以多种表面形式（如 "3DGS" vs "3D Gaussian Splatting"、"NeRF" vs "Neural Radiance Fields"）分散存储为多个 Neo4j 节点的问题。

**设计原则**：不使用正则表达式猜测缩写 — 去重决策基于上下文证据（确定性 `Full Name (ACRONYM)` 语法 + 同论文共现 + 跨论文首字母匹配）。

#### 4 层去重体系

| 层级 | 位置 | 机制 | 可靠性 |
|------|------|------|--------|
| 1 — 构建时规范化 | `graph_builder.py:_normalize_entity_name()` | 5 级流水线：自指代词拒绝 → `Full Name (ACRONYM)` 确定性解析 → 规范注册表 → 同论文共现 → 跨论文首字母匹配 | ~93% 召回（同论文共现） |
| 2 — Prompt 增强 | 3 类提取 prompt | LLM 始终使用 `3D Gaussian Splatting (3DGS)` 规范格式 | 增加 L1 命中率 |
| 3 — 构建后合并 | `graph_builder.py:_post_build_merge_aliases()` | 查询 Neo4j 同类型实体对，首字母启发式创建 `:ALIAS_OF` 关系 | 清理存量重复 |
| 4 — 检索时展开 | `graph_rag_engine.py:_expand_keyword_via_aliases()` | 在关键词检索中跟随 `:ALIAS_OF` 边展开别名 | 保证查询覆盖 |

#### 关键设计决策

- **`_is_short_name()`**：仅做长度门控（2 ≤ len ≤ 8，无空格），intentionally permissive。实际去重决策使用上下文证据，而非正则猜测。
- **同论文共现**（Layer 1, Stage 4）为最可靠的自动化方法：若 `_is_short_name(acronym)` 通过且 `_initials_of(full_name) == _normalize_acronym_key(acronym)`，则在同一论文内关联。
- **`_normalize_acronym_key()`** 去除连字符/点号（`GPT-3` → `GPT3`），解决带连字符缩写的首字母比较问题。
- **`:ALIAS_OF` 是非破坏性的**：不删除别名节点，仅创建关系链接到规范名。保留 query-ability 同时使别名语义显式化。

#### 新增辅助函数

| 函数 | 位置 | 说明 |
|------|------|------|
| `_is_short_name(name)` | `graph_builder.py` | 长度门控：2 ≤ len ≤ 8 且无空格 |
| `_initials_of(name)` | `graph_builder.py` | 提取首字母缩写（`3D Gaussian Splatting` → `3DGS`） |
| `_normalize_acronym_key(name)` | `graph_builder.py` | 去除连字符/点号后大写（`GPT-3` → `GPT3`） |
| `_FULL_NAME_WITH_ACRONYM` | `graph_builder.py` | 确定性正则：`Full Name (ACRONYM)` 模式 |
| `_post_build_merge_aliases()` | `graph_builder.py` | 构建后 Neo4j 别名合并（两阶段：收集 + 批量写入） |
| `_expand_keyword_via_aliases()` | `graph_rag_engine.py` | 检索时 `:ALIAS_OF` 展开 |

#### 实体类型守卫

`_normalize_entity_name()` Layer 2 新增实体类型名称 guard：若 `full_name` 本身是 9 种 closed-set 实体类型名称之一，跳过缩写注册，防止 "Method (Baseline)" 等伪模式产生误报。

#### 新增 Neo4j 关系类型

| 关系 | 方向 | 说明 |
|------|------|------|
| `:ALIAS_OF` | `(alias)-[:ALIAS_OF]->(canonical)` | 缩写指向规范全名（如 `3DGS` → `3D Gaussian Splatting`） |

#### 代码审查修复

### 飞书导出 — 正则表达式移除与规范化章节体系

**核心变更**：彻底移除 `_find_figure_anchor` 和 `_clean_figure_references` 中的正则表达式，用 `str.find()` + 逐字符扫描替代。定义 8 个规范化章节标题，LLM prompt 强制要求精确格式，`_normalize_section_headings()` 在运行态归一波折号、空格等变体。

**规范化章节标题**：

```python
CANONICAL_SECTIONS = [
    "## 1. 背景动机", "## 2. 相关工作", "## 3. 方法论",
    "## 4. 创新点", "## 5. 实验Benchmark", "## 6. 挑战与解决方案",
    "## 7. 下一步计划", "## 8. 参考文献",
]
```

**双锚点体系**：引用图表插入到相关工作末尾（`related_work` 锚点），方法论图表插入到方法论末尾（`methodology` 锚点）。`_find_section_anchor()` 用 `str.find()` 精确定位章节边界，不再依赖正则或模糊匹配。

**空白归一化**：`_normalize_section_headings` 在匹配前去除空格/制表符，容错 LLM 在中文与英文间插入空格（如 "实验 Benchmark" → "实验Benchmark"）。

**图表引用清洗**：`_clean_figure_references()` 用逐字符扫描替代正则，移除 LLM 编造的 "如图 X 所示" 引用（支持范围号、逗号/顿号分隔变体），保留句号不破坏句子完整性。

**锚点重新计算**：`create_feishu_document` 在 `_strip_markdown_images` 后从 `clean_text` 重新计算 `figure_anchors`，确保锚点文本在实际上传的文档中存在，消除 `--selection-with-ellipsis` 匹配失败。

**引用格式清理**：所有 prompt 移除加粗要求（`[**论文全名**]` → `[论文全名]`），正文引用仅保留链接。
