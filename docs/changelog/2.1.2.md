# [2.1.2] - 2026-05-22

## PaperBanana 本地服务集成、Feishu 导出管线修复与多模态增强

本次更新集成了 PaperBanana 本地服务以支持方法流程图自动生成，修复了 Feishu 文档导出管线中的多项关键问题，并增强了多模态提取（逻辑图注、表格渲染）和引用验证机制。

---

### PaperBanana 本地服务集成

**核心变更**：插件现在可以启动和管理本地 PaperBanana 服务，替代外部依赖。新增 `paperbanana_project_path` 配置项，启动时自动使用 PaperBanana 项目 `.venv` 中的 Python 启动本地生成服务。

| 文件 | 变更 |
|------|------|
| `idea/paperbanana.py` | 新增 `_start_local_server()`、`_stop_local_server()`、`_is_server_running()` 方法；`generate_method_figure()` 改为调用本地服务 API；自动生命周期管理 |
| `_conf_schema.json` | 新增 `paperbanana_project_path` 配置项（string，默认 `AstrBot/data/PaperBanana`），用于指定 PaperBanana 项目路径 |
| `main.py` | 初始化时传入 `self.config` 给 IdeaEngine，使配置在 idea 引擎内可用 |

---

### Feishu 文档导出管线修复

**核心变更**：修复 `/idea tofeishu` 导出中的多个 CRITICAL 和 HIGH 级问题，包括 lark-cli vs MCP 网关选择、临时文件清理、错误日志增强。

| 问题等级 | 描述 | 文件 |
|----------|------|------|
| CRITICAL-2 | lark-cli vs MCP 网关选择：尾部图片使用 lark-cli（不支持 `--index`），位置图片始终使用 MCP，通过 `_last_non_image_idx` 预计算实现 | `idea/feishu_doc.py` |
| HIGH-1 | PaperBanana 临时文件清理：`data/temp/` 下的临时文件在上传完成后才清理，避免过早删除导致上传失败 | `idea/feishu_doc.py` |
| HIGH-2 | 图片块错误日志增强：当 image block 既无有效路径又无 base64 时，记录明确的 error 日志 | `idea/feishu_doc.py` |
| MEDIUM-2 | 替换 `__import__('re')` 为模块级 `import re`（3 处） | `idea/feishu_doc.py` |

### Feishu 导出 — Token 预算管理与引用分批处理

**核心变更**：长引用上下文现在支持分批 token 预算管理。通过 `count_tokens()` 精确计算 n_ctx 余量，超长引用自动分批 → 生成分摘要 → 合并，避免上下文溢出。同时支持将已验证的参考文献索引追加到引用上下文。

| 文件 | 变更 |
|------|------|
| `idea/feishu_doc.py` | `_generate_group_meeting_report()` 中 LLM 润色前引入 token 预算管理：单批次 vs 多批次分支，`_split_citations_into_batches()` 分批，合并多批摘要 |
| `idea/feishu_doc.py` | 追加 `verified_index`（已验证的参考文献索引）到 `citations_context` |
| `idea/generation.py` | 新增 `_build_verified_reference_index()` 方法：从 chunk metadata 的 `cited_references`（LLMReferenceParser + arXiv MCP 校验过的权威数据）构建结构化引用索引 |

### Docling 逻辑图注编号 (Plan A)

**核心变更**：使用 docling 原生 `caption_text()` API 提取论文真实图注/表注文本，从中解析逻辑编号（如 "Figure 3" → `Figure3`），替代之前基于每页计数器的简单命名。逻辑编号提取失败时回退到每页计数器。

| 文件 | 变更 |
|------|------|
| `rag/_docling_subprocess.py` | 新增 `_extract_logical_num(caption_text, prefix)` 函数，支持 "Figure 3"、"Fig. 3"、"图 1"、"表 2" 等中英文格式 |
| `rag/_docling_subprocess.py` | `main()` 中 PictureItem 处理逻辑：优先从 `element.caption_text()` 获取真实图注，提取逻辑编号；同编号冲突时加后缀 |
| `rag/_docling_subprocess.py` | 新增 `_cell_to_text(cell)` helper，统一表格单元格文本提取逻辑 |
| `rag/_docling_subprocess.py` | 修复 `_table_to_png_bytes()` 中的 PyMuPDF 坐标映射：`bbox.l/r` vs `bbox.t/b` 的正确 PDF→屏幕坐标转换 |

**核心变更**：当 TextToCypherRetriever 生成的 Cypher 查询因缺失 RETURN 子句未通过 Neo4j EXPLAIN 校验时，自动追加 `RETURN *` 并重试。

| 文件 | 变更 |

### 图片定位管线修复（lark-cli 中段插入 + `_normalize_figure_references` 重写）

**核心变更**：修复 `_normalize_figure_references` 在图片已由 `_append_figure_section` 嵌入 Related Work 后仍将其移至文档末尾（或转换为文本）的问题。新增连续图片的 `_last_anchor` 回退机制。修复 `_extract_inline_images` 中 `unquote()` 导致的路径解析失败。

| 问题 | 描述 | 文件 |
|------|------|------|
| CRITICAL | `_normalize_figure_references` fallback：未找到 `## 论文图表` 章节时，扫描全文 `![...](path)` 并移至新建附录，直接逆转 `_append_figure_section` 的嵌入。修复：无 `## 论文图表` 章节时直接返回 unchanged | `idea/markdown.py` |
| CRITICAL | `_normalize_figure_references` primary path：找到 `## 论文图表` 章节时，将正文图片（含 `_append_figure_section` 嵌入的）转为 `caption (path)` 纯文本，`_convert_paren_paths_to_markdown` 再将其转为 `![image](path)`，最终渲染为 `[图片: image](path)`。修复：正文图片保持不动，仅规范化论文图表章节内的裸路径 | `idea/markdown.py` |
| HIGH | 连续图片（如同一章节多张论文图表）仅第一张有 anchor，后续图片 `text_batch` 为空导致无 anchor 追加到文档末尾。修复：新增 `_last_anchor` 回退，连续图片复用上一个有效 anchor | `idea/feishu_doc.py` |
| MEDIUM | `_extract_inline_images` 仅使用 `unquote(path)` 后的路径检查 `os.path.exists()`，若磁盘路径含字面 `%XX` 则被错误解码导致检查失败。修复：先尝试原始路径，失败后再尝试解码路径 | `idea/markdown.py` |
