# [2.0.3] - 2026-05-11

## Neo4j Cypher 语法错误修复与安全加固

本次更新针对 TextToCypherRetriever 生成的非法 Cypher 语句（`CONTAINS` 出现在节点属性模式中、匿名关系变量等）进行全面加固，并在全项目范围内执行"禁止静默跳过"规则。

---

### Custom TextToCypher 提示模板

**新增 `_TEXT_TO_CYPHER_TEMPLATE`** (`graphrag/graph_rag_engine.py`)：

自定义的 Cypher 生成提示模板，替代 llama_index 默认模板。包含：

- **学术知识图谱 Schema**：9 类节点标签（Method、Model、Task、Dataset、Metric、Component、Limitation、Application、Baseline）及其语义说明
- **14 类关系语义**：ADDRESSES、PROPOSES、USES_COMPONENT、EVALUATED_ON、ACHIEVES、COMPARES_WITH、LIMITED_BY、APPLIES_TO、EXTENDS、TRAINS_ON、IMPLEMENTS、OUTPERFORMS、REQUIRES、ABLATES_ON
- **7 条显式规则**：
  1. 多跳查询中每个关系必须绑定变量，禁止匿名 `-[:TYPE]->`
  2. `CONTAINS` 仅允许在 WHERE 子句中使用，严禁出现在节点属性模式中
  3. Cypher 必须以 MATCH、CALL、MERGE 或 RETURN 开头
  4. 节点模式仅使用精确匹配；模糊匹配使用 `WHERE n.name CONTAINS 'keyword'`
  5. 不过滤 description 字段（常为空）
  6. 使用 OR 而非 AND 以提高召回率
  7. LIMIT 30
- **5 个正例查询**（单跳 WHERE 过滤、多跳精确匹配 + WHERE 组合）
- **2 个反例警告**（CONTAINS 在节点模式中、匿名关系变量）
- **强制 RETURN 格式**：`coalesce(h.name,'') AS head, labels(h)[0] AS head_type, type(r) AS relation, coalesce(t.name,'') AS tail, labels(t)[0] AS tail_type`

### 两阶段 Cypher 验证器

**新增 `_make_cypher_validator(graph_store)`** (`graphrag/graph_rag_engine.py`)：

返回一个 `(str) -> str` 验证回调，在 llama_index 的 `TextToCypherRetriever` 执行 Cypher 之前对其进行双重校验：

| 阶段 | 机制 | 说明 |
|------|------|------|
| Stage 1 | 首 token 关键字检查 | 快速本地检查 Cypher 是否以合法子句关键字开头（MATCH、CALL、CREATE、MERGE、RETURN 等 15 个） |
| Stage 2 | Neo4j EXPLAIN 预解析 | 将 `EXPLAIN <query>` 发送到 Neo4j 解析器——这是黄金标准，在语法错误到达执行层之前就捕获它们 |

两个阶段的校验失败时都会抛出明确的 `ValueError`，携带完整 Cypher 内容（截断至 500 字符），便于快速定位和修复。

**新增 `_VALID_CYPHER_STARTS`**：包含 15 个合法 Cypher 子句关键字（MATCH、CALL、CREATE、MERGE、RETURN、UNWIND、WITH、OPTIONAL、EXPLAIN、PROFILE、SHOW、DROP、LOAD、FOREACH、USE）。

**应用位置**：验证器通过 `cypher_validator` 和 `text_to_cypher_template` 参数注入到两处 `TextToCypherRetriever` 实例化点（`_create_graph_retriever` 和异步初始化路径）。
