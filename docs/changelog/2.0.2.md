# [2.0.2] - 2026-05-11

## Token 计数统一模块

### 新增 `rag/token_utils.py`

将分散在 `graph_builder.py`、`hybrid_parser.py`、`text_splitter.py` 等模块的 token 计数逻辑统一提取到独立模块：

- **`count_tokens(text)`** — tiktoken `cl100k_base` 精确计数（线程安全单例 encoder）
- **`count_embedding_tokens(text)`** — BGE-M3 tokenizer 计数（优先），回退到 tiktoken
- **`set_embedding_tokenizer(tok)`** / **`get_embedding_tokenizer()`** — 全局注册/获取 embedding tokenizer

所有 `len(text) // 4` 估算已替换为精确计算。`hybrid_parser.py` 的 overlap 计算也从字符估算改为 token 精确计数。

### 受影响模块

| 模块 | 变更 |
|------|------|
| `graphrag/graph_builder.py` | 移除本地 `count_tokens()` / `_get_token_encoder()`，改用 `from rag.token_utils import count_tokens` |
| `rag/hybrid_parser.py` | `_get_token_count()` 移除 `// 4` 回退；`_get_tokenizer()` 注册全局 tokenizer |
| `rag/text_splitter.py` | `_get_token_count()` 回退到 tiktoken 而非 `RuntimeError` |

| `test/test_token_stress.py` | import 改为 `rag.token_utils` |

## 图谱召回通道重构

### 知识图谱独立于 RRF 融合

知识图谱通道从 RRF 第四通道改为两阶段检索中的独立召回通道（Stage 1.6），与向量/BM25 不再走同一 RRF 融合：

- **单阶段路径**：仅 3 通道 RRF 融合（稠密向量 + 稀疏权重 + BM25）。图谱不参与。
- **两阶段路径**：Stage 1.5 ColBERT 重排序确定 top-6 摘要通道论文 → Stage 1.6 图谱独立召回补充 top-2 论文（不经过 ColBERT rerank，避免文本打分过滤结构相关论文）→ 合并去重最多 8 篇进入 Stage 2 chunk 检索。

### `_graph_recall_papers` 嵌套 async 修复

PGRetriever 内部通过 `asyncio_run()` 创建线程执行异步任务，线程内的 `CustomLLM.complete()` 调用 `asyncio.get_event_loop().run_until_complete()` 在新 loop 上触发嵌套 async。修复方案：

- 新增 `@staticmethod _graph_retrieve_sync()` — 在 `asyncio.to_thread()` 的子线程中先执行 `nest_asyncio.apply()`，patch 线程内新创建的 event loop，再调用同步 `retrieve()`
- `_graph_recall_papers()` 通过 `await asyncio.to_thread(self._graph_retrieve_sync, ...)` 在独立线程安全执行图谱检索
