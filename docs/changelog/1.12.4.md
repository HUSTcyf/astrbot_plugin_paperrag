## [1.12.4] - 2026-05-03

### 图谱检索融入 RRF 四通道融合

**架构重构**: Graph RAG 不再作为独立检索引擎运行，而是作为第四通道（Graph Channel）融入 `HybridRetriever` 的 RRF 分数融合。图谱实体匹配的 `chunk_id` 通过 boost 分数直接增强已召回的向量 chunks，而非引入无关文本。

- `rag/hybrid_rag.py` — `HybridRetriever` 新增 `graph_retriever` 和 `graph_weight` 参数，支持四路 RRF 融合（向量 + 稀疏 + BM25 + 图谱）
- `rag/hybrid_rag.py` — `_rrf_fusion` 新增 `graph_chunk_boost` 参数，图谱通道通过 `chunk_id` 映射到向量候选实现增强
- `rag/hybrid_rag.py` — 新增 Provenance Guard：过滤无 `file_name`/`chunk_id` 的图谱节点，防止无出处内容进入最终答案
- `rag/hybrid_rag.py` — `_ensure_retriever_initialized` 改为 `async` 以支持图谱检索器异步连接
- `commands/base.py` — `_get_engine` 使用 `threading.Lock` 双重检查锁保护初始化，拆分 `_create_engine_inner`
- `commands/base.py` — 新增 `_graph_engine` 缓存字段和 `_engine_lock`/`_auto_build_lock`/`_response_cache_lock` 并发安全锁
- `_conf_schema.json` — 新增 `graph_rrf_weight` 配置项（默认 0.2），废弃旧 `hybrid_alpha`

### 图谱引擎 Neo4j 专属化

移除自定义 `MemoryGraphStore`，统一使用 Neo4j 作为唯一存储后端。

- `graphrag/graph_rag_engine.py` — 删除 `MemoryGraphStore`（~400 行），`GraphRAGConfig.storage_type` 默认改为 `neo4j`
- `graphrag/graph_rag_engine.py` — `SimplePropertyGraphStoreAdapter` 改用直接 Cypher MERGE 语句写入实体，绕过 LlamaIndex `EntityNode` 的 name 截断问题
- `graphrag/graph_rag_engine.py` — `add_entity` 失败时返回 `None`（而非静默返回 name）
- `graphrag/graph_rag_engine.py` — 图/表实体添加支持幂等（已存在则跳过）
- `graphrag/graph_rag_engine.py` — 删除 `get_entity`、`get_neighbors`、`get_triplets` 等冗余方法
- `graphrag/graph_rag_engine.py` — 新增 `_CaseInsensitiveSynonymRetriever` 解决 LLM 同义词大小写不匹配问题
- `graphrag/graph_rag_engine.py` — Neo4j dump/restore 使用 `cypher-shell` 替代自定义导入导出
