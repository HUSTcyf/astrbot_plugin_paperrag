# [2.2.1] - 2026-05-27

## Reference Parsing Pipeline

### Features
- **Lowered LLM temperature from 0.3 to 0.1** for more deterministic structured extraction
- **Enhanced prompt** to emphasize complete, verbatim title copying without truncation
- **Token-based batch splitting**: references exceeding 16384 tokens auto-split at reference number boundaries. Uses tiktoken `cl100k_base` for precise token counting (via `rag.token_utils.count_tokens()`), replacing char-based estimation. Applied uniformly to both local and cloud LLMs.
- **Uniform threshold**: single 16384-token limit for all LLM types. No retry-on-quality-failure (removed 50% empty title → smaller batch re-parse).

### Refactor
- **`parse_reference_section()`**: batch split logic inlined directly. Splits when `count_tokens(ref_section) > 16384`. No `_do_parse_reference_section()` indirection.
- **`_split_reference_section_by_numbers()`**: `count_tokens()` per line instead of `len()`. Removed force-split fallback for oversized single lines.
- Removed `_is_cloud_llm()` and `_do_parse_reference_section()` — dead code after unification.

## Enrichment Performance

### OpenAlex Async Migration
- **`pyalex` → `httpx`** native async in `_search_openalex_candidates()`. Direct REST API call to `api.openalex.org/works`, matching the pattern used by Crossref/DataCite. Eliminates `asyncio.to_thread()` + `requests` thread-pool overhead.

### Parallel Enrichment
- **`_enrich_references()` serial → parallel**: each reference enriched independently via `asyncio.gather` + `Semaphore(10)`. Measured **5.4x speedup** (20.93s → 3.87s for 5 queries, or ~7 min → ~1.3 min for 100 refs).
- **Crossref rate limiting**: `_crossref_semaphore = Semaphore(3)` per `PaperLinkResolver` instance prevents HTTP 429 from parallel requests.

### Polluted Title Fallback
- When `raw_text` is insufficient for LLM re-extraction, **`ref.ref_title` itself is used as fallback input** to `_re_extract_reference()`. The LLM can extract a clean title from a polluted string like `[114] C. Hou, L. Peng, ... "PD-TPE: Parallel decoder..."`.

## New Commands

### Features
- **`/paper reparseref <filename>`**: Lightweight single-paper reference re-parse using PyMuPDF text extraction + LLM parsing. Does NOT touch chunks/embeddings. Admin only.
- **`/paper refstats -1`**: Now shows per-paper reference parse quality report (success/failure counts, sorted by failures). Lists all papers with completely failed reference parsing. Previously showed papers with zero references.

### Refactor

## Fallback Search for Reference Link Resolution

### Problem
LLM 提取的参考文献标题可能存在转写错误、截断或幻觉，导致 `PaperLinkResolver` 标题搜索失败，参考文献无法获得 DOI / arXiv 链接。

### Solution: 三层回退搜索（仅在 reparse 命令启用）

| 层级 | 策略 | 说明 |
|------|------|------|
| 1 — raw_snippet + author | 用 LLM 输出的原始参考文献文本片段（截取 300 字符）+ 作者提示搜索 | 原始文本包含真实标题的概率远高于 LLM 转写 |
| 2 — author + year + title keywords | 第一作者姓氏 + 年份 + 标题前 5 个词组合搜索 | 标题有误时用作者和年份信号补充 |
| 3 — raw_snippet only | 仅用原始参考文献文本搜索，不含作者提示 | 避免错误的作者信息误导匹配 |

**实现要点**：
- **Prompt 增强**：`SECTION_PARSE_PROMPT` 和 `BATCH_PARSE_PROMPT` 新增 `raw_snippet` 字段，要求 LLM 逐字输出原始参考文献文本
- **raw_snippet 存储**：`_parse_single_batch()` 将 `raw_snippet` 存入 `Reference.raw_text` 字段（原为 `""`）
- **`_enrich_references()` 新增 `enable_fallback_search` 参数**：默认 `False`（正常 ingestion 不变），reparse 命令传递 `True`
- **透传链路**：`process_references_with_llm()` → `parse_reference_section()` → `_enrich_references()`
- **日志增强**：回退成功计数 `enriched_by_fallback` 加入富化完成日志

### Behavior

| 场景 | enable_fallback_search | 行为 |
|------|----------------------|------|
| 正常 ingestion | `False`（默认） | 完全不变，无额外 API 调用 |
| `/paper reparseref` | `True` | 首轮失败后自动三层回退 |
| `/paper reparse_zero_ref` | `True` | 同上 |

## LLM Provider Integration

### Problem
`_call_llm()` bypassed the AstrBot provider entirely, making raw HTTP requests with hardcoded `max_tokens: 16384`. This caused:
- Gemini models unreachable (no OpenAI-compatible `/chat/completions` endpoint)
- Output truncation risk from `max_tokens` limit
- Provider config (proxy, timeout, key rotation) not used

### Solution
Refactored to use `provider.text_chat()` as primary path, raw HTTP as fallback.

### Refactor
- **`_call_llm()` dispatcher**: checks `self.llm_config.get("provider")` → `_call_via_provider()` or `_call_via_http()`
- **`_call_via_provider(prompt, provider, max_retries)`** [NEW]: calls `await provider.text_chat(prompt=prompt)` then extracts `response.completion_text`. All provider features (proxy, key rotation, API-native format) work automatically.
- **`_call_via_http(prompt, max_retries)`** [NEW]: original raw HTTP logic extracted, used for freeapi fallback. `max_tokens` set from config default (32768). Added `finish_reason == "length"` warning for truncation detection.
- **`_resolve_llm_config()` priority**: provider (when `text_provider_id` set) → freeapi (fallback for local VLM mode). Returns `{"provider": provider_obj}` for provider path.
- **Error logging**: `str(e)` → `{type(e).__name__}: {e!r}` to capture gRPC exceptions whose `str()` is empty.

### Display Name Fix
- **`_llm_display_name(llm_config)`** [NEW]: extracts human-readable model name from provider object or freeapi config. Fixes "Using LLM: unknown" when provider path is active.

## cited_ref_ids Sync After Reparse

### Problem
After `/paper reparseref` or `/paper reparse_zero_ref`, `paper_doc_stats.json` is updated with new references, but Milvus chunks still hold old `cited_ref_ids` in metadata. The reparse may change which `ref_id` maps to which reference, causing retrieval code to silently return wrong references.

### Solution
After reparse completes, re-run `CitationLinker` on the paper's Milvus chunks with the new references and upsert changed `cited_ref_ids` via `partial_update=True` (preserves vectors/text).

### Features
- **`HybridIndexManager.sync_cited_ref_ids_for_paper(file_name, references)`** [NEW]: queries Milvus chunks → runs CitationLinker → diffs old vs new `cited_ref_ids` → upserts changed chunks with `partial_update=True`. Handles `_file_name_has_pdf_suffix` matching, JSON string metadata parsing, index-based chunk correlation.
- **Integration into `_paper_reparseref`** and **`_paper_reparse_zero_ref`**: sync called automatically after successful reference re-parse, with progress/sync counts reported in output.

## Retrieval Robustness

- **`_build_verified_reference_index()`** in `idea/generation.py`: now logs `logger.warning()` when `ref_id` from chunk metadata is not found in `paper_doc_stats.json`, making silent data corruption visible.

## Smart Reference Repair

### Problem
部分论文在 ingestion 后存在未链接的参考文献（无 DOI / arXiv URL）。原因分两类：
- **Empty/polluted titles**: LLM 提取失败，title 字段含作者名、引用编号或 URL
- **Link resolution failure**: title 正确但 Crossref/OpenAlex 搜索未命中

针对这两类问题需要不同的修复策略，但之前缺乏自动诊断和批量修复机制。

### Solution: 智能自动分类 + 双策略修复

**`classify_papers_for_repair()`** 自动分析 `paper_doc_stats.json`，将论文分为两类：

| 策略 | 触发条件 | 方法 | 成本 |
|------|---------|------|------|
| **Full Reparse** | 任意 ref 的 title 为空或含污染（编号/作者名/URL） | PyMuPDF 文本提取 + LLM 解析 + 链接富化 | 高（LLM 调用） |
| **Link-Only Repair** | 所有未链接 ref 都有干净的合法标题 | 仅重跑 `PaperLinkResolver` 富化（Crossref/OpenAlex/arXiv） | 低（API 调用，无 LLM） |

### Features

- **`/paper repair_refs confirm`**: 一键智能修复。Step 1 解析 LLM config → Step 2 自动分类 → Step 3 双阶段执行（link-only 先，full reparse 后），含进度报告和最终统计。
- **`repair_links_for_paper(file_name, llm_config)`**: 轻量级单篇 link-only 修复。从 JSON 加载已有 ref → 转回 `Reference` 对象 → 仅对无链接的 ref 重跑 `_enrich_references()` → 保存回 `paper_doc_stats.json`。无 PyMuPDF，无 LLM 提取。
- **`LLMReferenceParser._looks_like_polluted_title()` 增强**: 新增信号 4 — URL 检测 (`^https?://`)，防止 LLM 将链接误认为标题。
- **`verify_unlinked_refs.py`**: 独立诊断/修复脚本。支持 `--execute`（运行修复）、`--link-only`（仅轻量修复）、`--full-only`（仅完整重解析）。自动备份 `paper_doc_stats.json`。
- **`HybridIndexManager.classify_papers_for_repair()`**: `classify_papers_for_repair()` 的包装方法，统一调用模式。
