# [2.2.1] - 2026-05-27

## Reference Parsing Pipeline

### Features
- **Lowered LLM temperature from 0.3 to 0.1** for more deterministic structured extraction
- **Enhanced prompt** to emphasize complete, verbatim title copying without truncation
- **Character-based batch splitting**: references exceeding 15000 chars auto-split at reference number boundaries with second-pass force-split for oversized batches. Replaced tiktoken-based approach which didn't properly bound batch sizes.

### Refactor
- **`parse_reference_section()`**: batch split logic inlined directly. Splits when `len(ref_section) > 15000`. No `_do_parse_reference_section()` indirection.
- **`_split_reference_section_by_numbers()`**: char-based splitting at reference number boundaries with second-pass force-split.
- Removed `_is_cloud_llm()` and `_do_parse_reference_section()` — dead code after unification.

## Enrichment Performance

### OpenAlex Async Migration
- **`pyalex` → `httpx`** native async in `_search_openalex_candidates()`. Direct REST API call to `api.openalex.org/works`, matching the pattern used by Crossref/DataCite. Eliminates `asyncio.to_thread()` + `requests` thread-pool overhead.

### Parallel Enrichment
- **`_enrich_references()` serial → parallel**: each reference enriched independently via `asyncio.gather` + `Semaphore(10)`. Measured **5.4x speedup** (20.93s → 3.87s for 5 queries, or ~7 min → ~1.3 min for 100 refs).
- **Crossref rate limiting**: `_crossref_semaphore = Semaphore(3)` per `PaperLinkResolver` instance prevents HTTP 429 from parallel requests.

### Polluted Title Fallback
- When `raw_text` is insufficient for LLM re-extraction, **`ref.ref_title` itself is used as fallback input** to `_re_extract_reference()`. The LLM can extract a clean title from a polluted string like `[114] C. Hou, L. Peng, ... "PD-TPE: Parallel decoder..."`.

## Fallback Search for Reference Link Resolution

### Problem
LLM-extracted reference titles may contain transcription errors, truncation, or hallucination, causing `PaperLinkResolver` title search to fail, leaving references without DOI/arXiv links.

### Solution: 4-Tier Multi-Source Fallback Chain

| Tier | Source | Description |
|------|--------|-------------|
| 1 | Crossref → OpenAlex → arXiv Library | Multi-source academic API resolution (existing) |
| 2 | arXiv MCP | DOI-based exact search (existing) |
| 3 | Semantic Scholar | Free title match API, ~1 req/sec rate limited [NEW] |
| 4 | DDG Web Search | Extracts DOI/arXiv from DuckDuckGo search results [NEW] |

`enable_fallback_search` defaults to `True` in `process_references_with_llm()` — fallback tiers 3-4 run for ALL reference parsing, not just reparse/repair commands.

## LLM Provider Integration

### Problem
`_call_llm()` bypassed the AstrBot provider entirely, making raw HTTP requests with hardcoded `max_tokens: 16384`. This caused:
- Gemini models unreachable (no OpenAI-compatible `/chat/completions` endpoint)
- Output truncation risk from `max_tokens` limit
- Provider config (proxy, timeout, key rotation) not used

### Solution
Refactored to use `provider.text_chat()` as primary path, raw HTTP as fallback.

### Refactor
- **`_call_llm()` dispatcher**: checks `self.llm_config.get("provider")` → `_call_via_provider()` or `_call_via_http()`
- **`_call_via_provider(prompt, provider, max_retries)`** [NEW]: calls `await provider.text_chat(prompt=prompt)` then extracts `response.completion_text`. All provider features (proxy, key rotation, API-native format) work automatically.
- **`_call_via_http(prompt, max_retries)`** [NEW]: original raw HTTP logic extracted, used for freeapi fallback. `max_tokens` set from config default (32768). Added `finish_reason == "length"` warning for truncation detection.
- **`_resolve_llm_config()` priority**: provider (when `text_provider_id` set) → freeapi (fallback for local VLM mode). Returns `{"provider": provider_obj}` for provider path.
- **Error logging**: `str(e)` → `{type(e).__name__}: {e!r}` to capture gRPC exceptions whose `str()` is empty.

### Display Name Fix
- **`_llm_display_name(llm_config)`** [NEW]: extracts human-readable model name from provider object or freeapi config. Fixes "Using LLM: unknown" when provider path is active.

## cited_ref_ids Sync After Reparse

### Problem
After `/paper reparseref` or `/paper reparse_zero_ref`, `paper_doc_stats.json` is updated with new references, but Milvus chunks still hold old `cited_ref_ids` in metadata. The reparse may change which `ref_id` maps to which reference, causing retrieval code to silently return wrong references.

### Solution
After reparse completes, re-run `CitationLinker` on the paper's Milvus chunks with the new references and upsert changed `cited_ref_ids` via `partial_update=True` (preserves vectors/text).

### Features
- **`HybridIndexManager.sync_cited_ref_ids_for_paper(file_name, references)`** [NEW]: queries Milvus chunks → runs CitationLinker → diffs old vs new `cited_ref_ids` → upserts changed chunks with `partial_update=True`. Handles `_file_name_has_pdf_suffix` matching, JSON string metadata parsing, index-based chunk correlation.
- **Integration into `_paper_reparseref`** and **`_paper_reparse_zero_ref`**: sync called automatically after successful reference re-parse, with progress/sync counts reported in output.

## Retrieval Robustness

- **`_build_verified_reference_index()`** in `idea/generation.py`: now logs `logger.warning()` when `ref_id` from chunk metadata is not found in `paper_doc_stats.json`, making silent data corruption visible.

## Smart Reference Repair

### Problem
部分论文在 ingestion 后存在未链接的参考文献（无 DOI / arXiv URL）。原因分两类：
- **Empty/polluted titles**: LLM 提取失败，title 字段含作者名、引用编号或 URL
- **Link resolution failure**: title 正确但 Crossref/OpenAlex 搜索未命中

针对这两类问题需要不同的修复策略，但之前缺乏自动诊断和批量修复机制。

### Solution: 智能自动分类 + 双策略修复

**`classify_papers_for_repair()`** 自动分析 `paper_doc_stats.json`，将论文分为两类：

| 策略 | 触发条件 | 方法 | 成本 |
|------|---------|------|------|
| **Full Reparse** | 任意 ref 的 title 为空或含污染（编号/作者名/URL） | PyMuPDF 文本提取 + LLM 解析 + 链接富化 | 高（LLM 调用） |
| **Link-Only Repair** | 所有未链接 ref 都有干净的合法标题 | 仅重跑 `PaperLinkResolver` 富化（Crossref/OpenAlex/arXiv） | 低（API 调用，无 LLM） |

### Features

- **`/paper repair_refs confirm`**: 一键智能修复。Step 1 解析 LLM config → Step 2 自动分类 → Step 3 双阶段执行（link-only 先，full reparse 后），含进度报告和最终统计。
- **`repair_links_for_paper(file_name, llm_config)`**: 轻量级单篇 link-only 修复。从 JSON 加载已有 ref → 转回 `Reference` 对象 → 仅对无链接的 ref 重跑 `_enrich_references()` → 保存回 `paper_doc_stats.json`。无 PyMuPDF，无 LLM 提取。
- **`LLMReferenceParser._looks_like_polluted_title()` 增强**: 新增信号 4 — URL 检测 (`^https?://`)，防止 LLM 将链接误认为标题。
- **`verify_unlinked_refs.py`**: 独立诊断/修复脚本。支持 `--execute`（运行修复）、`--link-only`（仅轻量修复）、`--full-only`（仅完整重解析）。自动备份 `paper_doc_stats.json`。
- **`HybridIndexManager.classify_papers_for_repair()`**: `classify_papers_for_repair()` 的包装方法，统一调用模式。

- `rag/reference_processor.py` — `classify_papers_for_repair()`, `repair_links_for_paper()`, `_looks_like_polluted_title()` URL 检测

## Batch Splitting: Token → Character-Based

### Problem
Token-based batch splitting (`tiktoken cl100k_base`, 16384-token limit) only checked token counts at `[N]` line boundaries, causing batches to balloon to 34000+ chars. Serial processing made reference parsing take 24+ minutes for 4 batches.

### Solution
- **Reverted to character-based splitting** (15000 chars ≈ 4000 tokens). `_split_reference_section_by_numbers` splits at reference number boundaries with a second pass to force-split any oversized batches.
- Removed tiktoken dependency entirely.

## LLM Call Multi-Path Refactoring

### Provider Path
- **Gemini**: Direct `generate_content_stream` with `thinking_budget=0` — bypasses provider wrapper to disable thinking mode which causes server-side timeout on structured output tasks
- **Stream-capable providers**: `text_chat_stream()` with `is_chunk` filtering — keeps connection alive for long requests
- **Other providers**: `text_chat()` with 910s timeout — timeout mutation + restore pattern
- **DeepSeek/GLM thinking disable**: `_call_via_http` auto-sets `"thinking": {"type": "disabled"}` for GLM and DeepSeek models to prevent reasoning tokens from breaking JSON parsing
- **Short-response guard**: Responses < 50 chars trigger 5s sleep + retry (handles concurrent pressure garbage responses)

### Provider Config Priority
Provider LLM first (with OpenAI-compatible types extracting direct HTTP fallback config from `provider_config`), freeapi as HTTP fallback.

## Reference Link Resolution: 4-Tier Fallback Chain

Replaced the old 3-tier raw_snippet fallback with a 4-tier academic + web search chain:

```
_enrich_references()
  ├── 1. PaperLinkResolver (Crossref → OpenAlex → arXiv Library)
  ├── 2. arXiv MCP (DOI exact search)
  ├── 3. Semantic Scholar (free title match API, ~1 req/sec rate limited)
  └── 4. DDG Web Search (ddgs library, extracts DOI/arXiv from search results)
```

### Semantic Scholar Fallback
- `_resolve_via_semantic_scholar(title)` — `GET /graph/v1/paper/search/match`
- Free, no API key, rate-limited to ~1 req/sec via `_ss_last_request` class-level throttle
- 404 = no match (silent skip), 429 = rate limited (skip remaining batch)

### DDG Web Search Fallback
- `_resolve_via_web_search(title)` — uses `ddgs` library (`ddgs.DDGS`)
- `asyncio.wait_for(timeout=60.0)` prevents hanging on unresponsive DDGS calls
- Regex-extracts DOI and arXiv ID from all search result hrefs and bodies
- Covers dataset papers and technical reports not in academic indexes

### `enable_fallback_search` Default Changed
Changed from `False` to `True` in `process_references_with_llm()` — fallback now runs for all reference parsing, not just reparse/repair commands.

### Removed
- BrightData MCP (`rag/web_search.py` deleted) — account suspended, replaced by Semantic Scholar + DDG
- `web_search_fn` parameter from `PaperLinkResolver.__init__`

## arXiv API Serialization & Health Check Fix

### Problem
8 concurrent `_search_arxiv_library_candidates` calls via `asyncio.gather(Semaphore(10))` all hit arXiv simultaneously, causing immediate HTTP 429. The existing `_MIN_ARXIV_INTERVAL` timestamp check was ineffective under concurrency — all coroutines checked `_last_arxiv_request_time` at the same moment.

### Solution
- **`asyncio.Lock` serialization**: `_arxiv_lock` ensures only one coroutine calls arXiv API at a time
- **`num_retries=0`**: `arxiv.Client(num_retries=0)` — no automatic 3×3s retries on 429
- **Health check uses real query**: `query="deep learning"` instead of `"test"` — `"test"` always returned cached HTTP 200, giving false confidence
- **Init-time 429 detection**: `_ensure_arxiv_health_check()` disables arXiv for entire session on first 429 — no runtime re-detection needed
- **Clock unified**: All timing uses `time.monotonic()` consistently
