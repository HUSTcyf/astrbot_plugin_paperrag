# [2.0.1] - 2026-05-08

## 评估 LLM 客户端健壮性增强

### 自动重试机制

`evaluation/ragas_generator.py` 的 `OpenAICompatibleLLM` 新增 3 次自动重试（指数退避 1s→2s→4s），覆盖同步和异步两条路径：

- **`agenerate_text()`**：提取 `_do_agenerate_request()` 单次请求方法，外层重试循环捕获 `asyncio.TimeoutError` 和 `RuntimeError`
- **`_call_api()`**：同步路径重试循环捕获 `requests.Timeout`、`requests.ConnectionError`、`requests.RequestException`
- 所有超时统一为 300 秒（async `ClientTimeout`、sync `requests timeout`、embeddings 请求）

### OpenAI 客户端加固

`evaluation/ragas_evaluator.py` 中 Ragas 评分阶段的两个 `openai.OpenAI` 客户端（LLM + Embedding）配置：
- `max_retries=5` — OpenAI SDK 内置重试
- `timeout=httpx.Timeout(300.0, connect=30.0)` — 防止 vapi 代理无响应永久挂起

### 超时日志改进

- `asyncio.TimeoutError` 的空字符串 `str()` 问题已通过 `type(e).__name__` 显式标注
- `_generate_answer()` 的超时/失败日志标注 "(3次尝试均失败)" 明确重试已耗尽

## BM25 检索修复

### 两阶段检索移除 BM25 的 paper_id 过滤

`rag/hybrid_rag.py` 两阶段检索阶段 2 中，BM25 结果不再被 `paper_id_set` 过滤。BM25 的核心优势是跨全集精确词匹配，先前将其限制在语义抽象筛选后的 top-8 论文内，导致相关论文未被 abstract 检索命中时 BM25 结果被丢弃（如 CF-3DGS 等专有方法名）。

### `is_exact_match_query()` 模式扩展

BM25 触发条件从仅检测数字/引用/符号扩展为：

| 新增模式 | 覆盖场景 |
|---------|---------|
| `\b[A-Z]{2,}\b` | 全大写缩写：DTU, LERF, RMSE, SAC, ICL, SDF |
| `[A-Z][a-z]+[A-Z][a-z]*` | CamelCase 方法名：SparseNeRF, PointNeRF, InstantNGP, TartanAir |
| `who ... is/are/was/were` | 人物身份事实查询 |
| `what role/contributions does/did` | 人物角色/贡献查询 |

> 注：CamelCase 模式不使用末尾 `\b`（word boundary），因为连续大写字母后无 word boundary（如 "SparseNeRF" 中 RF 连续）。
