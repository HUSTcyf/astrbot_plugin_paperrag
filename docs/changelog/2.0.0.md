# [2.0.0] - 2026-05-07

## 架构重构

### provider/ 模块 — 统一模型服务层

将散落在 `idea/`、`agentic_rag/`、`commands/` 中的 LLM 调用逻辑统一到顶层 `provider/` 模块：

- **`provider/llama_cpp_vlm.py`** — 从 `idea/llama_cpp_vlm_provider.py` 移动，本地 Llama.cpp VLM 单例
- **`provider/llm_utils.py`** — 新增统一 LLM 调用封装：
  - `get_llm_provider()` — 4 步优先级 provider 解析链（config → VLM → session → inst_map）
  - `call_llm()` — 完整 LLM 调用：解析 provider → text_chat → 提取文本
  - `call_llm_json()` — LLM 调用 + JSON 解析
  - `extract_text_from_response()` — 兼容 VLM、AstrBot cloud provider（result_chain）、dict 多格式

全项目 17 处 import 已更新为 `from provider.llm_utils import ...` / `from provider.llama_cpp_vlm import ...`。

### Agentic RAG 节点统一使用 call_llm

`agentic_rag/nodes/` 和 `idea/nodes/` 中所有 LLM 调用点统一使用 `call_llm()` / `call_llm_json()`，消除重复的 provider 解析 → text_chat → 文本提取内联代码（每个调用点减少 10-15 行）。

### 配置驱动 LLM 参数

新增 `text_llm_temperature` 和 `text_llm_max_tokens` 配置项，所有 `call_llm()` / `call_llm_json()` 调用统一从插件配置读取默认值，优先级：调用方显式传入 > config 配置 > 函数默认值。

## GBNF Grammar 修复

### 根因定位

llama.cpp GBNF parser 将换行视为规则边界，多行 `idea` 规则被截断为两行，第二行被误解析为错误的规则定义。同时前向引用（规则使用在定义之前）导致 `expecting name` 错误。

### 修复

- **`idea/idea_schema.gbnf`** 完全重写：拓扑排序（`ws` → `esc` → `chars` → `strval` → `strarray` → `floatval` → `idea` → `array` → `root`）+ 单行 `idea` 规则
- 验证：`LlamaGrammar.from_file()` 解析通过，4B 模型端到端推理通过（所有 8 字段正确，feasibility=0.85）

## LLM 调用的 Config 线程化

### 4 个节点补传 config

- `react_agent.py` / `synthesize.py` → `call_llm(prompt, context, state.get("_config"))`
- `debate.py` / `critique.py` → `call_llm_json(prompt, context, state.get("_config"), ...)`
- `idea/agentic_workflow.py` → `run_agentic_ideas()` 新增 `config` 参数，注入 state

### Regular RAG 路径统一

`commands/retrieval_helpers.py` 的 `_generate_rag_answer()` 改用 `call_llm()`，删除 80 行重复代码（`_get_text_llm_provider` + `_extract_provider_text` + 两个辅助方法），Regular RAG 和 Agentic RAG 共享同一套 provider 解析。

### 配置提示修正

`_conf_schema.json` 移除 `text_llm_temperature` / `text_llm_max_tokens` 中误导性的"自动"提示（不存在自动切换温度/token 的机制）。

## Bug 修复

- **Demo report coroutine bug**：`tools/generate_demo_report.py` 两处 `_get_local_vlm_provider()` 漏 `await`，导致 Regular RAG 侧全部报 `'coroutine' object has no attribute 'text_chat'`，对比报告 4/4 失败。已修复。
- **GBNF segfault**：`idea/idea_schema.gbnf` 多行规则导致 llama.cpp 解析失败后 segfault。重写后修复。
- **AstrBot cloud provider 响应提取**：`extract_text_from_response()` 新增 `result_chain` 格式支持，修复云 provider 路径文本提取失败。
- **Config 覆盖显式参数**：`call_llm()` 中 config 不再覆盖调用方显式传入的 `temperature`/`max_tokens`（sentinel 模式）。
