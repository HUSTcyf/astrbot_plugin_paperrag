## [1.12.2] - 2026-04-23

### 本版补充 - 论文链接解析、ColBERT 持久化与配置收口

**概述**: 将论文摘要、标题和 URL 提取收敛到同一条入库链路，统一优化 ColBERT 存储保存逻辑，并清理掉已废弃的插件配置项。当前 `/paper add`、`/paper rebuild` 与离线构建都会在同一流程中完成摘要、标题和 URL 解析。

**命令入口变化**:
- `/paper abstract_build confirm [N]` 已退役并移入 `legacy/`，默认插件只保留主线入库与重建入口
- `main.py` 进一步按功能域收口，主文件只保留插件壳、命令注册与共享入口

**模型路径与默认值变化**:
- `embedding_mode` 默认值调整为 `unsloth`，不再保留 `ollama`
- `ollama` 相关配置与路径分支已移除，避免不同入口对路径解析出现歧义
- Graph / idea 相关的本地模型路径统一按插件根目录解析，修复子目录误找模型的问题

**链接解析与摘要入库**:
- `rag/abstract_index.py` 作为摘要索引事实来源，统一执行标题提取、摘要提取和 URL 解析
- `PaperLinkResolver` 统一处理 `PDF 元数据 -> 首页文本 -> Crossref -> OpenAlex -> arXiv library` 的解析顺序
- `HybridRAGEngine.add_papers()` 继续复用 parser 已提取的标题 / 摘要 hint，避免重复解析同一份 PDF
- `milvus_abstracts_doc_stats.json` 清空与重建行为收敛，`clear/rebuild` 时会直接写回 `{}`，避免旧状态残留
- 标题占位串、作者行、特殊字符前缀（如 `π0` / `π0.5`）等边角情况得到进一步修正

**ColBERT 持久化**:
- `rag/colbert_storage.py` 的三份持久化文件固定写入插件 `data/` 目录：
  - `colbert_doc_vectors.npy`
  - `colbert_faiss_index.bin`
  - `colbert_id_mapping.json`
- `HybridRAGEngine.add_papers()` 在 `enable_multi_vector_rerank=true` 时会强制初始化 retriever，确保第一次入库也能正常绑定 reranker 并写盘
- `model is None` 时不再直接跳过后续流程，而是仅跳过 ColBERT 向量预计算并打印明确报错，避免静默失保存
- ColBERT 存储加载提示已降噪，首次构建、文件不完整、真正加载失败分别给出不同日志

**配置收口**:
- 删除废弃配置项：`enable_noise_filter`、`reranking_model`、`reranking_device`、`reranking_adaptive`、`reranking_threshold`、`reranking_batch_size`
- 统一 ColBERT 重排序开关为 `enable_multi_vector_rerank`
- 保留并恢复 BM25 为正常可用配置，不再标记为废弃
- `enable_sparse_retrieval`、`sparse_top_k`、`hybrid_alpha`、`hybrid_rrf_k`、`enable_bm25`、`bm25_top_k` 已完整接入插件入口与评估脚本
- `sparse_top_k` 不再被 `bm25_top_k` 反向覆盖，稀疏召回与 BM25 召回可以独立调节
- `enable_sparse_retrieval` 现在会真正控制稀疏召回是否执行

**文档与测试**:
- 新增并维护 `test/test_link_resolution_probe.py`，用于整库 URL 探测与人工回归
- 新增 `test/test_abstract_index_flow.py`，覆盖摘要、标题和 URL 一次入库流程
- README 和配置 schema 已同步更新，减少重复或过时配置项的误导

### 稳定性修复 - LLM compaction 解耦与健壮性增强

**概述**: 将 LLM compaction 逻辑从 `hybrid_parser.py` 分离为独立 mixin，并修复多处运行时健壮性问题。

**新增**:
- `rag/llm_compaction.py` - LLM compaction mixin 类（`_compact_text_with_llm`, `_llm_compact_single`, `_parse_llm_compact_response`, `_preprocess_documents_with_llm`），通过多继承方式接入 `HybridPDFParser`
- `rag/llm_preprocessor.py` - LLM 预处理模板常量（`LLM_COMPACT_PROMPT_TEMPLATE`, `LLM_COMPACT_WITH_META_PROMPT_TEMPLATE`, `remove_reference_sections`）
- `rag/paper_link_resolver.py` - 论文内部链接解析器（新增依赖模块）
- `rag/parser_types.py` - 解析器类型定义（新增依赖模块）
- `rag/pdf_document_parser.py` - PDF 解析器 mixin 基类（新增依赖模块）
- `rag/text_splitter.py` - 文本分块器（新增依赖模块）
- `test/test_chunk_tokenization.py` - 分块 tokenization 单元测试

**重构**:
- `HybridPDFParser` 改为多继承：`class HybridPDFParser(PDFDocumentParserMixin, LLMCompactionMixin)`
- `_ensure_llm_provider_initialized` 改为 `async def`，不再使用 `loop.run_until_complete`（避免事件循环嵌套）
- 表格路径格式改为 `caption|page_num|idx` 字符串键，避免类型不匹配
- 图片存储完全由 docling 处理（移除 `_save_image_to_disk` 方法）

**修复**:
- LLM compaction 非破坏式降级：LLM 异常或空结果时回退到 raw_text，不再中断 PDF 导入流程
- `abstract_index.clear()` 删除 collection 后断开 Milvus 别名连接，避免下次初始化报 "Alias already creating connections" 错误
- `_get_token_count` 当 tokenizer 不可用时回退到 `len(text) // 4` 字符计数，不再中断分块
- chunk overlap 方向修复：`tokens[-overlap_tokens:]` 替代 `tokens[:overlap_tokens]`
- 修复 abstract index 删除/清空时 abstract_manager 状态未清理的问题
- 大型 HTTP 响应日志截断至前 200 字符
- `figures_dir` 路径修复：`Path(__file__).parent.parent` 正确指向插件根目录（原来是 `.parent`，少了一层）
- `LocalGGUFClient` 新增 `is_placeholder_title()` 判断，过滤文件名/arXiv ID 等占位标题
- `embedding_mode` 规范化：旧配置值 `api` → `astrbot`，`ollama` → `unsloth`

**代码质量**:
- 移除约 28 处冗余局部导入（`import re`, `import os`, `import json`, `from pathlib import Path` 等），涉及 `rag/hybrid_rag.py`, `rag/llm_compaction.py`, `rag/hybrid_parser.py`, `main.py`, `rag/multimodal_extractor.py`, `legacy/rag/hybrid_rag.py`, `evaluation/ragas_generator.py`, `evaluation/run_evaluation_ragas.py` 等 9 个文件
- `hybrid_parser.py` 从 1701 行缩减至约 1175 行（-31%）

**配置变更**:
- `main.py` RAGConfig 新增 `core_api_key`、`use_arxiv_api` 参数
- `main.py` RAGConfig 移除 `ollama_config` 参数
