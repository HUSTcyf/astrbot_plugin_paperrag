A Retrieval-Augmented Generation system for academic paper search and question-answering, built as a plugin for the AstrBot framework. The plugin registers commands (/paper search, add, addf, delete, rebuild, abstract_build, graph_build, arxiv_add, refstats) and exposes LLM tools (search_papers, retrieve_papers) for tool-use mode. The system employs a two-stage retrieval architecture:

STAGE 1 — Abstract Index (AbstractIndexManager): When papers are added, LocalGGUFClient extracts abstracts using a local Qwen3.5-9B GGUF model (Qwen3.5-9B-UD-Q4_K_XL.gguf + mmproj-BF16.gguf) via llama-cpp-python, with automatic fallback from 9B to 4B model (Qwen3.5-4B-UD-Q4_K_XL.gguf). If GGUF is unavailable, falls back to rule-based AbstractExtractor (keyword detection: "abstract", "摘要", "summary"). Extracted abstracts are embedded by AstrBotEmbeddingProvider (whatever provider is configured in AstrBot: Gemini API, Ollama, etc.) or OllamaEmbeddingProvider and stored in a dedicated Milvus collection (paper_abstracts) with fields: paper_id, file_name, title, abstract_text, vector (FLOAT_VECTOR, COSINE metric, AUTOINDEX). At query time, the user query is embedded and searches this abstract collection to return top-k relevant paper_ids, dramatically reducing the chunk search space.

STAGE 2 — Chunk Retrieval (HybridRAGEngine): Within the filtered paper set, HybridPDFParser parses PDFs via Docling/PyMuPDF, extracting MultimodalPDFExtractor producing: ExtractedImage (page_number, image_index, bbox, image, image_bytes, base64_data, caption), ExtractedTable (page_number, table_index, html, markdown, csv), ExtractedFormula (page_number, formula_index, text). Semantic chunking splits content at sentence boundaries with configurable overlap (default chunk_size=512, overlap=50), producing Node dataclasses: {text: str, metadata: Dict[str, Any]}. Nodes are indexed in a second Milvus collection (paper_embeddings, alias: "hybrid_index") with BM25 index (rank_bm25) for keyword search. Hybrid retrieval combines VectorRetriever (cosine similarity) and BM25Retriever, fused via Reciprocal Rank Fusion: Score = Σ 1/(k+rank), k=60. Optional ContentReranker applies BAAI/bge-reranker-v2-m3 cross-attention reranking with adaptive threshold.

Query Intent Routing (GraphRAGRouter): Classifies incoming queries via pattern matching — entity-relation patterns (e.g., "X和Y的关系") route to GRAPH_LOCAL; definition/technical patterns (e.g., "什么是X", "如何实现X") route to VECTOR; trend patterns (e.g., "X的发展趋势") route to GRAPH_GLOBAL. Falls back to HYBRID or AUTO mode.

Knowledge Graph Augmentation (GraphRAGEngine): MultimodalGraphBuilder extracts knowledge triples (Entity1, Relation, Entity2) via LLM prompting with entity types: Model/Architecture (BERT, GPT, Transformer), Method/Technique (attention, pooling), Task (text classification, QA), Dataset (GLUE, ImageNet), Metric (accuracy, F1, BLEU), Optimizer/Algorithm (Adam, SGD), Framework/Library (PyTorch, TensorFlow), Author/Organization, Venue (NeurIPS, ACL), and Other. Storage backends: PersistentPropertyGraphStoreAdapter (LlamaIndex SimplePropertyGraphStore with JSON persistence) or Neo4jGraphStore (Bolt protocol + Cypher queries via LlamaIndex PropertyGraphIndex). Graph retrieval supports local traversal (entity → neighbors, depth=2) and global traversal (Louvain community detection).

Multimodal VLM (LlamaCppVLMProvider): Loads Qwen3.5-9B GGUF model via llama-cpp-python with 9B→4B automatic fallback, n_ctx=4096, n_gpu_layers=99. Handles image QA queries and table understanding via rendered images.

Generation Layer: Retrieved Node passages with scores are combined with the original query and optional graph context into an augmented prompt, fed to AstrBot's GLM provider or local LlamaCpp VLM. CitationLinker parses bibliography and links citations in the generated response.

Storage Architecture: Two Milvus Lite collections on SQLite (milvus_papers.db, milvus_abstracts.db) in data/. File system stores extracted figures (data/figures/{paper_id}/) and tables (data/tables/{paper_id}/). JSON document statistics (paper_doc_stats.json) tracks file_name, added_time, chunk_count, vector_ids per paper.

Technology Stack: AstrBot SDK (plugin framework), PyMuPDF/Docling (PDF parsing), Milvus Lite (vector DB), AstrBotEmbeddingProvider/Ollama (embeddings), BAAI/bge-reranker-v2-m3 (reranking), llama-cpp-python GGUF (local VLM), LlamaIndex PropertyGraphStore/SimplePropertyGraphStore (graph storage), rank_bm25 (keyword search), CORE API (arXiv download).
